# Model coverage backlog

These are acceptance criteria for extending financial coverage. The private Nintendo demonstration and the website's filing-check behavior can be tested independently.

| Gap | Acceptance evidence required |
| --- | --- |
| GD V4 statement depth | A live output with historical and projected income statements, balance sheets and cash-flow statements, supporting schedules, and documented rounding tolerances. Tie the statements for every period. |
| Company-specific forecasts | Trace revenues to operating drivers such as hardware units and software attachment, with dates and sources. Explain the basis of long-run growth, risk spread, reinvestment and terminal returns. |
| Peer valuation and equity bridge | Include dated, eligible peers and calculated multiples. Reconcile post-balance changes in cash, debt, other claims and diluted shares to the price comparison date. |
| Institutional report | Match the verified model, show industry context, thesis, catalysts, bull and bear cases, and identifiable risks. Issue a rating only when the evidence supports one. |
| Broader live coverage | Repeat credentialed hosted generation for GD, NVDA, FAST, SBUX and DHR. Record each issuer's actual data or modeling failure separately from configuration and provider failures. Count a pass only after both downloaded files open, their valuations agree and the workbook fingerprint matches. |

The Nintendo pilot uses guidance for the stub period and a sales-growth assumption thereafter. The current report documents a scenario, leaves trading comparables for review and withholds a recommendation.
